# 测试策略（长期标准，2026-11-01 起生效）

## 用户长期要求

所有测试必须按三个方向组织并全部执行，每个层次都覆盖**功能性**与**健壮性**：

| 层次 | 范围 | 功能性 | 健壮性 |
|------|------|--------|--------|
| 单元（Unit） | 纯逻辑：解析器、格式化、队列、分类器、协议帧 | 正常输入输出、边界值 | 空值、非法输入、极端值 |
| 集成（Integration） | 跨层协作：客户端↔服务↔队列（真实 HTTP 通道 + 进程内假引擎） | 状态刷新、暂停/继续、并发调度 | RPC 错误、超时、单点失败不毁全局 |
| 系统（System） | 端到端链路：链接→补全→分类→入队→引擎→状态回流 | 全流程出结果（含真实用户输入场景） | 引擎故障注入（错误/500/进程挂）→状态保留→恢复 |
| 暴力（Brute） | 模糊输入、大数据、并发压测（2026-11-01 起为长期必跑层） | 大数据量分块往返字节级一致、混合文本提取 | 2 万条随机输入不崩不卡、随机操作压测并发不越界、攻击面（路径遍历/保留名/控制字符）全拦 |

## 执行要求

- 每次交付前三层全跑全绿；沙箱报告按层次汇报数量与结果。
- 假引擎（StubAria2Server）支持按 gid 定制状态与故障注入（JSON-RPC 错误 / HTTP 500），是集成与系统测试的共用基础设施。
- 界面层（WinUI3）无法在 Linux 编译，以人工核对 XAML/C# 为准；Core/Engine/Host 层全部可自动测。
- 新功能须先补对应层次的测试再交付；修 bug 必须带回归测试。

## 目录结构

```
src/TaoDown.Core.Tests/
├── Unit/          纯逻辑单元测试
├── Integration/   跨层集成测试（含假引擎基础设施）
├── System/        端到端系统测试（含故障注入与恢复）
└── Brute/         暴力测试（模糊/压测/攻击面，每次交付必跑）
```
